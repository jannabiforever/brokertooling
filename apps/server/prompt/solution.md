# 해설 원고 쓰기

## 무엇을 하는가

문제 하나를 받아 직접 풀고, 장재원팀 해설 양식에 그대로 옮겨 넣을 수 있는 **본문 원고**를 텍스트 파일로 만든다.

- 입력: 문제(이미지, PDF, hwpx, 텍스트). 정답이 같이 오면 검산에 쓴다.
- 출력: `<코드>해설원고.txt` (UTF-8). 문제마다 파일 하나.
- 한글 파일, 머리말 표, 문제 그림은 만들지 않는다. 그건 haeseol-scaffold의 일이다.

원고는 사람이 읽고 고치기도 하지만, 나중에 줄 단위로 hwpx에 옮겨질 것이다. 그래서 형식 규칙(줄 = 문단, `$…$` = 수식 개체)과 수식 띄어쓰기 규칙을 정확히 지키는 것이 문장을 잘 쓰는 것만큼 중요하다. 수식 표기가 가이드와 다르면 편집 담당자가 수식을 하나하나 다시 열어 고쳐야 한다.

## 순서

### 1. 문제 읽기

- 문제 전문을 작업 메모로 정확히 옮겨 적어 본다(원고에는 넣지 않는다). 첨자, 부등호 방향, 등호 포함 여부, "단, …" 조건을 특히 본다.
- 이미지가 흐려서 한 글자라도 확신이 없으면 추측하지 말고 사용자에게 그 부분을 묻는다. 조건 하나를 잘못 읽으면 원고 전체가 버려진다.
- 코드(예: `S-841`, `Y574`)와 정답이 주어졌는지 확인한다. 코드는 원고 파일 이름에만 쓰고, 정답은 검산과 답글에만 쓴다. 코드가 없으면 문제 파일명에서 따오고, 그래도 없으면 `미정`으로 둔다.

### 2. 풀기와 검산

- 원고를 쓰기 전에 끝까지 푼다. 풀면서 쓰지 않는다.
- 셸이 있으면 계산은 코드로 한 번 더 돌린다(sympy가 없으면 설치하거나 `fractions`·수치 계산으로 대신한다). 근·극값·적분·급수 값처럼 손계산이 길어지는 곳이 대상이다.
- 구한 답이 문제의 **모든** 조건을 만족하는지 거꾸로 대입해 본다. 필요조건만 따라가서 얻은 답은 조건을 깨는 경우가 있다. 이 검산은 여기서 끝내고 원고에는 쓰지 않는다.
- 주어진 정답과 다르면 원고를 쓰지 말고 멈춘다. 어디서 갈리는지 정리해 사용자에게 알린다. 정답에 풀이를 끼워 맞추지 않는다.

### 3. 풀이 경로 정하기

해설은 "답이 맞다는 증명"이면서 동시에 "시험장에서 이렇게 생각하면 된다"는 안내다. 그래서:

- 조건 해석 → 구조 파악(개형, 주기, 대칭, 중복도 등) → 계산 순서로 짠다.
- 수능 교육과정 안의 도구만, 그것도 그 문항의 과목 범위 안에서 쓴다(수학Ⅱ 문항에 이계도함수나 미적분 공식을 끌어오지 않는다). 로피탈, 테일러 전개도 쓰지 않는다.
- 문제에 나온 대상을 그대로 해석한다. 보조 함수를 여러 개 새로 정의해 대수적으로 밀기보다 "곡선 y=f(x)와 직선 …의 교점의 개수"처럼 그래프로 읽는 쪽이 이 해설의 방식이다.
- 새 문자가 필요하면 문제에 이미 쓰인 문자와 겹치지 않게 고른다.
- 경우를 나눌 때는 빠진 경우가 없게 하고, 버리는 경우마다 **왜 안 되는지**를 한 줄이라도 쓴다.
- 그림이 있어야 이해되는 상황(개형, 접선, 교점 개수)이면 그림 자리를 잡아 둔다. 그림은 사용자가 직접 그린다.

### 4. 원고 쓰기

아래 「원고 형식」, 「분량과 깊이」, 「문체」, 「수식 문법」, 「수식 띄어쓰기」를 따른다.

### 5. 점검

아래 「점검」의 논리 점검을 하고, 형식 점검 스크립트를 돌린다. 통과한 뒤 파일을 전달한다.

### 6. 전달

- 파일을 보낸다(SendUserFile 등). 수식 문법에 백틱과 `~`가 들어가므로 원고를 채팅에 마크다운으로 붙이지 않는다. 꼭 보여줘야 하면 코드 블록 안에 넣는다.
- 답글은 짧게: 정답, 풀이 흐름 두세 줄, 그리고 사용자가 손봐야 할 것(그림 자리 개수, `<<일러` 표시 개수, 확신이 낮은 수식 표기, 문제 판독이 애매했던 곳).

## 원고 형식

```
(본문)

$therefore `` {1} over {60}$
```

- 파일에는 해설 본문만 넣는다. 코드, 정답, 제목 같은 머리 줄을 맨 위에 쓰지 않는다. 첫 줄이 곧 해설의 첫 문장이다.
- **한 줄 = 한글 문서의 한 줄(문단)** 이다. 빈 줄은 빈 줄 그대로다.
- **수학과 관련된 수식은 전부 `$…$` 안에** 쓴다. 본문 속 숫자 하나, 문자 하나도 수식 개체다. `$3$ 이상의 홀수 $n`$에 대하여`처럼 쓴다. `$`밖에는 한글과 문장부호, (가)·(나)·ㄱ·ㄴ·①·㉠ 같은 표지, 그리고 수학과 무관한 숫자(문항 번호`04번`, `[그림 1]`)만 남는다.
- `$…$` 안에는 한글 수식 편집기 문법만 쓴다. LaTeX(`\frac`, `\sqrt` 등)를 쓰지 않는다.
- 조사는 수식 바로 뒤에 띄어쓰기 없이 붙인다. 이때 수식 끝에 백틱 하나가 들어간다(「수식 띄어쓰기」 참고): ``$f LEFT( x RIGHT)`$는``, ``$t=20`$을``.
- **따로 떼어 보이는 식(별행 수식)** 은 앞뒤에 빈 줄을 두고, 줄 맨 앞을 공백 4개로 들여 쓴다. 탭 문자는 원고 어디에도 쓰지 않는다. 별행 줄에 한글이 섞여도 된다.
- 쉼표는 좌표·구간·순서쌍의 쉼표만 수식 안에 넣는다. 그 밖에 식을 여러 개 나열할 때는 식마다 `$…$`로 나누고 쉼표는 밖에 둔다: ``세 점 $rm A`$, $rm B`$, $rm C$``. 문자 뒤에 범위를 달 때도 수식을 따로 써서 한 칸 띄운다: ``$1-d`$, $1+d$ $LEFT( d>0 RIGHT)`$이라 하면``. 한글이 섞이는 범위는 ``($N`$은 정수)``처럼 괄호를 밖에 둔다. `$` 밖에 둔 괄호는 평문이므로 `LEFT`·`RIGHT`를 붙이지 않는다.
- 별행 수식을 여러 줄 나열할 때는 들여 쓴 줄을 빈 줄 없이 잇는다.
- 식 번호는 식 뒤에 `$cdots$ ㉠`처럼 붙이고, 본문에서는 ``㉠[반띄쓰]에 $t=20`$을 대입해``처럼 부른다.
- 원문자(①, ㉠ 등)나 (가)·(나) 같은 괄호 표지 바로 뒤에 글자가 이어지면, 띄어 쓰지 않고 그 사이에 `[반띄쓰]`라는 글자를 그대로 넣는다: `(가)[반띄쓰]조건`, `㉠[반띄쓰]의 양변`, `①[반띄쓰]이라면`. 편집할 때 반 칸 띄어쓰기로 바꿀 자리라는 표시다. `(가) 조건`처럼 띄어 쓰지 않는다. 표지 뒤가 띄어쓰기·쉼표·마침표이거나 줄 끝이면 넣지 않는다(`    ① 두 접점 …`, `$cdots$ ㉠`, `(가), (나)[반띄쓰]조건`).
- 그림 자리는 그 그림을 처음 언급한 문단 바로 아래에 한 줄로 적는다: `[그림 1: 무엇을 어떻게 그릴지]`(그림이 하나뿐이면 번호 없이 `[그림: …]`). 이 줄은 수식 개체가 아니라 그리는 사람에게 남기는 메모이므로 `$` 없이 평문(y=f(x), (5, f(1)))으로 쓰고, 길어도 된다. 곡선·직선의 식, 표시할 점과 좌표, 접하는지 여부까지 적어서 이 줄만 보고 그릴 수 있게 한다.
- 본문에서 그림을 부를 때는 그림이 하나면 "오른쪽 그림과 같이", 둘 이상이면 `[그림 1]과 같이`, `([그림 1] 참고)`로 쓴다. 본문 줄을 `[그림`으로 시작하지는 않는다(그림 자리 줄과 구분되지 않는다).
- 수식 안에 한글을 넣어야 하는 경우(조건별 함수의 "n이 홀수인 경우" 등)는 그 줄 끝에 한 칸 띄우고 `<<일러`를 붙인다. 수식 안 한글은 글씨체가 달라 일러스트레이터 작업으로 교체해야 해서, 편집 담당자가 놓치지 않게 하는 표시다.
- 마지막 줄은 `$therefore` (답)$ ``이다. 객관식이어도 번호가 아니라 **값**을 쓴다. p+q처럼 가공된 값을 묻는 단답형은 최종값만 쓴다. 합답형은 `$therefore$ ㄱ, ㄷ`.

## 분량과 깊이

해설은 증명이 아니다. 읽는 사람은 문제를 한 번 풀어 본 상위권 수험생과 검토자이고, 알고 싶은 것은 "어떤 관찰로 구조가 정해지는가"다. 모든 단계를 엄밀하게 메우면 정작 그 관찰이 묻힌다.

- 분량 기준: 본문이 빈 줄 포함 40~70줄, 최고난도 문항도 130줄 안팎이다. 이보다 길어지면 증명을 쓰고 있는 것이다.
- 잘 알려진 성질이나 전형적인 관찰은 한두 줄로 **말하고 넘어간다.** 증명하지 않는다. 아래가 이 해설의 밀도다.

```
공비가 유리수인 등비수열에서,
정수인 두 항 사이에는 정수가 아닌 유리수인 항이 존재할 수 없으므로
(나)[반띄쓰]조건에서 제시된 항은 연속된 세 항임을 쉽게 눈치챌 수 있고
등비중항의 성질을 고려하면 이들 중 중앙에 오는 항은 $6`$임 또한 알 수 있다.
```

- 개형, 교점의 개수, 부호 판단은 그림과 `개형 상`, `임을 쉽게 알 수 있다`에 맡긴다. 함숫값의 부호를 구간마다 나열해 사잇값 정리로 근의 개수를 세는 식의 서술은 하지 않는다.
- 뻔한 계산은 `대입하여 정리하면`, `이를 정리하면`으로 건너뛰고 결과 식만 보인다.
- 줄여도 빠지면 안 되는 것은 세 가지다: 경우를 버리는 이유, 거짓인 보기의 반례, 식을 세우는 근거가 되는 사실. 검토자가 되묻는 곳이 여기다.

## 문체

### 문장이 식을 품는다

이 해설의 가장 큰 특징이다. 식을 문장 밖에 따로 세워 두지 않고, 한 문장이 별행 수식을 가운데 끼고 이어진다. 식 앞 줄은 마침표 없이 끊기고, 식 다음 줄이 조사나 어미로 시작해 문장을 닫는다.

```
이때, $alpha `$, $beta `$는 이차방정식

    $x ^{2} + LEFT( -x+2 RIGHT) ^{2} =t$

의 서로 다른 두 실근이다. 여기서 근과 계수의 관계를 이용하면

    $beta - alpha = sqrt {2t-4}$

임을 쉽게 얻는다.
```

식 뒤를 닫는 말로 자주 쓰는 것: `이다.` / `임을 얻는다.` / `임을 얻을 수 있다.` / `임을 알 수 있다.` / `을 얻는다.` / `이어야 한다.` / `가 성립한다.` / `으로 정리된다.` / `라고 둘 수 있다.` / `와 같이 나타낼 수 있다.` / `이라는 조건으로 바꿔 해석할 수 있다.`

식 뒤 조사는 **식의 마지막 기호를 소리 내어 읽었을 때**의 받침에 맞춘다.

- 받침 있음(`이`·`을`·`은`·`으로`·`이라`): 숫자 0·3·6·10, 문자 m·n, ㉠·㉡
- ㄹ 받침(`이`·`을`·`은`이지만 `로`): 숫자 1·7·8, 문자 l·r
- 받침 없음(`가`·`를`·`는`·`로`·`라`): 숫자 2·4·5·9, 그 밖의 문자(a, b, d, k, p, q, t, x, y, α, β, π …)
- 분수는 "a분의 b"로 읽으므로 분자를, 닫는 괄호(`RIGHT)`)로 끝나면 괄호 안 마지막 기호를 따른다.
- 애매하면 `이다.`, `임을 얻는다.`처럼 받침과 무관한 말로 닫는다.

### 줄을 짧게 끊는다

한 줄에 한 호흡만 담는다. 쉼표나 연결어미(`~이므로`, `~이고`, `~하면`) 뒤에서 줄을 바꾸고, 한 줄이 화면에 보이는 길이로 대략 40자를 넘지 않게 한다(수식은 스크립트 글자 수가 아니라 조판된 모습으로 센다).

```
만약 삼차함수 $f LEFT( x RIGHT)`$의 $x-n pi$ 중복도가 $1`$이라면,
적당한 이차식 $Q` LEFT( x RIGHT)`$에 대하여 $f LEFT( x RIGHT) = LEFT( x-n pi RIGHT) Q` LEFT( x RIGHT)`$라 둘 수 있고
이때 $Q` LEFT( n pi RIGHT) != 0`$이므로 주어진 극한은
```

생각의 단위가 바뀌면 빈 줄 하나, 풀이의 큰 국면이 바뀌면(조건 (가) 해석이 끝나고 (나)로 넘어갈 때 등) 빈 줄 둘을 둔다.

### 말투

- 평서문 `-이다`체. 독자를 이끌 때만 `~하자`, `~해보자`를 쓴다: `이제 (나)[반띄쓰]조건을 해석해보자.`, `이제 정적분의 값을 계산하자.`
- 연결어: `먼저` `이때` `따라서` `한편` `또한` `즉` `이제` `이에 따라` `이를 고려하면` `이를 정리하면` `여기서`
- 문자를 새로 둘 때: `편의를 위해 … 라 하면`, `일반성을 잃지 않고, … 라 하자.`
- 경우를 버릴 때: `만약 … 이라면, (식) 이 되어 (가)[반띄쓰]조건에 위배된다. 따라서 … 이다.` / `… 이어야 하는데 이는 … 임에 모순이다.`
- 가능한 값이 하나로 좁혀질 때: ``가능한 정수 $n`$은 $-4`$뿐이다.``
- 조건을 부를 때: `(가)[반띄쓰]조건에서`, `(나)[반띄쓰]조건에 따르면`, `박스 조건으로부터`, `주어진 부등식은`
- 전형적인 관찰이나 짧은 계산은 `쉽게 얻는다`, `쉽게 알 수 있다`, `쉽게 눈치챌 수 있다`로 넘긴다. 경우를 버리는 대목과 반례에는 쓰지 않는다.
- 한 줄 안에서 식이 식을 낳을 때는 식을 화살표에서 나누어 `$A$   $RARROW$   $B$`처럼 쓴다. 두 식과 화살표가 각각 수식 개체이고, 화살표 양옆은 공백 세 칸이다. 동치일 때는 `$LRARROW$`를 같은 꼴로 쓴다. `$A ~~ RARROW ~~ B$`처럼 한 수식 안에 화살표를 넣지 않는다. 근거는 식 끝에 ` LEFT( because`d>0 RIGHT) ``로 단다.
- 경우를 나열할 때는 공백 4개로 들여 쓰고 `① …`, `② …`로 적은 뒤 `만약 ①[반띄쓰]이라면,`으로 받는다.

### 끝맺음

마지막 문단은 ``따라서 구하는 $…`$의 값은 $…`$이다.`` 꼴로 묻는 것에 답하고, 빈 줄 뒤에 `$therefore` …$ `` 줄을 둔다.

### 합답형(ㄱㄴㄷ)

보기에 들어가기 전에 공통으로 쓰이는 식·조건을 먼저 정리하고 `이제 ㄱ, ㄴ, ㄷ의 참, 거짓을 차례대로 판별해 보자.`로 넘어간다. 각 보기는 다음 틀을 따른다.

```
ㄱ.

(판별 과정)

$therefore$ (참)


ㄴ.

(판별 과정)

$therefore$ (거짓)
```

거짓인 보기는 **구체적인 반례**를 식으로 제시한다. "그런 함수는 무수히 많다"로 끝내지 않는다.

마지막 보기의 `$therefore$ (참)` 뒤에는 맺는 문장 없이 빈 줄 하나를 두고 `$therefore$ ㄱ, ㄷ`으로 끝낸다.

## 수식 문법 (한글 수식 편집기)

스크립트의 스페이스는 토큰을 구분할 뿐 화면에 나오지 않는다. 그래서 명령어는 앞뒤를 반드시 띄운다. `npi`는 글자 세 개로 읽히므로 `n pi`로 쓴다. 화면에 보이는 간격은 백틱(짧은 띄어쓰기)과 `~`(긴 띄어쓰기)로만 만든다.

```
분수            {a} over {b}        분자·분모는 항상 중괄호. 겹치면 {4} over {400 times {{3} over {5}}}

도함수          f`' LEFT( x RIGHT)   f`'' LEFT( x RIGHT)   (프라임은 위 첨자 없이 ' 로)
역함수·합성     f ^{-1} LEFT( x RIGHT)   LEFT( f ^{-1} RIGHT)`' LEFT( x RIGHT)   g circ f

그리스 문자     alpha  beta  theta  pi …

확률·통계       rm P it LEFT( A RIGHT)   rm E it LEFT( X RIGHT)   rm V it LEFT( X RIGHT)   (P·E·V는 로만체, 뒤는 it으로 되돌림)

주의할 것:

- **로만체**: 점, 선분, 도형의 이름과 확률·통계의 P, E, V는 `rm`으로 로만체로 쓴다. sin, cos, tan, log, ln은 자동으로 로만체가 된다. 그 밖의 문자는 기본 이탤릭이다.
- **`rm`의 범위**: `rm`은 뒤를 전부 로만체로 바꾸고, 중괄호로 묶어도 그 밖까지 이어진다. 그래서 뒤에 이탤릭이 이어지면 `it`으로 되돌린다: ``rm A it LEFT( a`,``b RIGHT)`, ` rm P it `LEFT( X geq {k} over {2} RIGHT) ``, `` bar {rm AB} it`=2 sqrt {t-2} `. `{rm A} LEFT( a`,``b RIGHT)``나 `{rm P} LEFT( X=k RIGHT)`처럼 중괄호로만 가두면 a, b, X, k까지 로만체가 된다. 한 수식에 로만체가 여러 번 나오면 그때마다 `rm … it`을 쓴다. 뒤에 숫자·기호만 오거나 수식이 거기서 끝나면 `it`은 필요 없다(`` $rm A`$ `, ` bar {rm AB} `=1 ``).
- **명령어와 철자가 겹치는 이름**: 삼각형 BAR를 `rm BAR`로 쓰면 `bar` 명령어로 읽힌다. 한 글자를 중괄호로 끊는다: `rm {B}AR`. 명령어는 대소문자를 가리지 않으므로(그리스 문자만 예외) 점 이름을 이어 쓸 때 늘 확인한다.
- **`<-`는 화살표가 된다**: `x<-1`은 "x←1"로 조판된다. 부등호를 중괄호로 끊는다: `x{<}-1`. 음수가 오른쪽에 오는 부등식에서 자주 걸린다.
- **선분의 길이는 `bar`**: `bar {rm AB}`. `overline`을 쓰지 않는다.
- **괄호는 항상 `LEFT`·`RIGHT`**: 수식 안의 소괄호·중괄호·대괄호는 내용의 높이와 상관없이 전부 `LEFT( … RIGHT)`, `LEFT{ … RIGHT}`, `LEFT[ … RIGHT]`로 쓴다. 예외가 없다. 함수의 인수(`f LEFT( x RIGHT)`), 좌표·구간·순서쌍, 곱셈의 괄호(`LEFT( x-1 RIGHT) LEFT( x+2 RIGHT)`), 범위(`LEFT( d>0 RIGHT)`), `because` 근거, `cases`의 조건, 겹친 괄호의 안쪽까지 모두 해당한다. `$…$` 안에 맨 괄호 `(` `)` `[` `]`가 하나도 남지 않아야 한다.
  - 여는 쪽과 닫는 쪽의 개수를 맞춘다. 반열린구간처럼 모양이 달라도 된다: ``LEFT( 0`,``1 RIGHT]``.
  - `LEFT(`와 `RIGHT)`는 명령어이므로 앞뒤 토큰과 띄어 쓴다: `fLEFT(x RIGHT)`가 아니라 `f LEFT( x RIGHT)`.
  - 문법용 중괄호(`{a} over {b}`, `^{2}`, `cases{ }`, `eqalign{ }`)는 화면에 나오는 괄호가 아니므로 그대로 둔다. 반대로 화면에 보여야 하는 중괄호(수열 `LEFT{ a _{n} RIGHT}`, 집합)는 `LEFT{ RIGHT}`로 쓰지 않으면 아예 조판되지 않는다.
  - `$` 밖의 괄호((가), (참), ``($N`$은 정수)``, 그림 자리 줄)는 수식이 아니므로 대상이 아니다.
- **조건별 함수**: 케이스 사이에 빈 줄 하나를 둔다(`# & #`).
- 등호나 `RARROW`가 여러 줄로 이어지는 계산은 수식 하나에 `eqalign`으로 묶는다. 줄마다 수식을 따로 만들면 정렬이 맞지 않는다. 이때의 `RARROW`는 `eqalign` 안에 그대로 둔다. 식을 나누어 쓰는 것은 한 줄에 놓이는 `A ⇒ B` 꼴뿐이다(「말투」 참고).
- 표에 없는 기호는 LaTeX 이름에서 역슬래시를 뗀 것이 대개 통한다. 확신이 없으면 그대로 쓰되, 답글의 "손봐야 할 것"에 그 식을 적어 둔다.

- "수식 끝" 규칙이 가장 자주 쓰이고 가장 자주 빠진다. 본문 속 수식 대부분은 뒤에 조사가 붙으므로 백틱으로 끝난다. 뒤에 띄어쓰기가 오는데 백틱까지 넣으면 간격이 두 배가 되므로, 그때는 넣지 않는다. 별행 줄에서도 기준은 같다. 수식 뒤에 쉼표나 한글이 바로 붙으면 넣고, 줄이 거기서 끝나면 넣지 않는다. 화살표에서 나눈 식(`$A$   $RARROW$   $B$`)은 뒤가 띄어쓰기이므로 끝에 백틱을 넣지 않는다.
- 이탤릭 대문자 규칙은 글자가 오른쪽으로 기울어 다음 글자와 붙어 보이는 것을 막는 것이다. 로만체(`rm`)로 쓴 점 이름이나 확률·통계의 P, E, V에는 적용하지 않는다.
- 괄호를 모두 `LEFT`·`RIGHT`로 쓰더라도 띄어쓰기 규칙은 그대로다. "함수 이름과 키 큰 괄호 사이" 백틱은 괄호 안에 지수·분수·근호가 있어 괄호가 실제로 커질 때만 넣고, `f LEFT( x RIGHT)`처럼 내용이 낮으면 넣지 않는다. 수식 끝 백틱은 `RIGHT)` 뒤에 붙인다: ``$f LEFT( x RIGHT)`$는``.
- 여기 없는 상황에서 간격이 좁거나 넓어 보일 것 같으면 임의로 정하지 말고 답글의 "손봐야 할 것"에 적는다.

## 예시 (S-841, 객관식)

문제: t>2인 실수 t에 대하여 원 x²+y²=t가 직선 y=−x+2와 만나는 서로 다른 두 점을 A, B라 할 때, ∠AOB=f(t)라 하자. 미분가능한 함수 f(t)에 대하여 f′(20)의 값은? (단, O는 원점이다.)

```

이때, $alpha `$, $beta `$는 이차방정식

    $x ^{2} + LEFT( -x+2 RIGHT) ^{2} =t$

의 서로 다른 두 실근이다. 여기서 근과 계수의 관계를 이용하면

    $beta - alpha = {sqrt {4 ^{2} -4 times 2 times LEFT( 4-t RIGHT)}} over {2} = sqrt {2t-4}$

임을 쉽게 얻는다.


한편, $bar {rm AB} it `= sqrt {2} LEFT( beta - alpha RIGHT) =2 sqrt {t-2} `$, $bar {rm AO} `= bar {rm BO} it `= sqrt {t} `$이므로

    $4t-8=2t times LEFT( 1- cos`f LEFT( t RIGHT) RIGHT)$   $RARROW$   $cos`f LEFT( t RIGHT) = {4} over {t} -1$ $cdots$ ㉠

    $-f`' LEFT( t RIGHT) times sin`f LEFT( t RIGHT) =- {4} over {t ^{2}}$   $RARROW$   $f`' LEFT( t RIGHT) = {4} over {t ^{2} times sin`f LEFT( t RIGHT)}$ $cdots$ ㉡

    $f`' LEFT( 20 RIGHT) = {4} over {400 times {{3} over {5}}} = {1} over {60}$

$therefore `` {1} over {60}$
```

```

## 점검

### 논리

- 묻는 것에 답했는가. `∴` 줄의 값이 본문 마지막 결론, 주어진 정답(번호라면 그 선지 값)과 같은가.
- 식을 세울 때 쓴 사실(예: f′(4)=0, 연속, 정의역)을 그 식보다 **앞에서** 한 번 밝혔는가.
- 경우 나눔에 빠진 경우가 없는가. 버린 경우마다 이유가 있는가.
- 합답형에서 거짓인 보기에 구체적 반례가 있는가.
- 적분 변수가 위끝·아래끝의 문자와 겹치지 않는가(`int _{0} ^{x} f LEFT( t RIGHT) dt`).
- 같은 대상을 가리키는 문자가 도중에 바뀌지 않는가. 새로 둔 문자는 범위(`LEFT( d>0 RIGHT)`, `(N은 정수)`)를 밝혔는가.
- 문제의 모든 조건이 한 번씩은 쓰였는가. 안 쓰인 조건이 있으면 풀이가 틀렸을 수 있으니 다시 본다. 답을 가르지 않는 조건이라도 풀이 어디에서 쓰이는지는 드러나야 한다.
- 분량이 「분량과 깊이」의 기준 안인가. 넘으면 증명처럼 쓴 대목을 한두 줄로 줄인다.

### 형식

셸이 있으면 아래를 `check.py`로 저장해 `python3 check.py 원고.txt`로 돌린다. 아무것도 출력되지 않으면 통과다. 경고가 나오면 원고를 고치고 다시 돌린다.

```python
import re, sys
CMD = {"times", "div", "over", "RARROW", "LARROW", "LRARROW", "leq", "geq", "because", "therefore", "~~", "~"}
def check_eq(i, eq, nxt, prev):
    def w(msg): print(i, msg + ":", eq)
    body = eq.strip()
    if "\\" in eq: w("LaTeX 역슬래시")
    if eq.count("{") != eq.count("}"): w("중괄호 짝")
    if re.search(r"(?<![A-Za-z])(n|\d)pi\b|[a-z]sin|sinx|cosx|tanx", eq): w("명령어 붙여 씀")
    if " over " in eq and not re.search(r"\}\s*over\s*\{", eq): w("over 양쪽 중괄호")
    if "overline" in eq: w("선분 길이는 bar")
    if re.search(r"\bneq\b|<=|>=", eq): w("부등호는 != leq geq")
    if re.search(r"<\s*-", eq): w("<- 는 화살표가 됨, {<}- 로")
    ends = body.endswith("`")
    if nxt and not nxt.isspace():
        if not ends: w("뒤에 글자가 붙는데 끝 백틱 없음")
        elif re.search(r"(?<![A-Za-z])[CEPQRS]`$", body) and "rm" not in eq and not body.endswith("``"): w("이탤릭 대문자로 끝나면 백틱 둘")
    elif ends and not body.startswith("therefore"): w("뒤가 띄어쓰기·줄 끝인데 끝 백틱 있음")
    if prev.endswith("제") and nxt in ("항", "사") and not body.startswith("`"): w("제n항·제n사분면은 앞에도 백틱")
    for m in re.finditer(",", eq):
        if not eq[:m.start()].rstrip().endswith("`") or not eq[m.end():].lstrip().startswith("``"): w("쉼표 앞 백틱 하나, 뒤 둘"); break
    if "rm" not in eq:
        if re.search(r"(?<![`'])'", eq): w("프라임 앞 백틱")
        if re.search(r"(?<![A-Za-z])[CEPQRS](?!\s*[`_^])(?![A-Za-z])", eq): w("이탤릭 대문자 C·E·P·Q·R·S 뒤 백틱")
    for m in re.finditer(r"\b(?:sin|cos|tan)\b", eq):
        rest = re.sub(r"^\s*\^\s*\{[^}]*\}", "", eq[m.end():]).lstrip()
        if rest and rest[0] not in "`})": w("sin·cos·tan과 각 사이 백틱"); break
    for m in re.finditer(r"(\S+)\s+(?:sin|cos|tan|log|ln)\b", eq):
        t = m.group(1)
        if t not in CMD and t[-1:].isalnum() or (t.endswith(("}", ")")) and not t.startswith(("_{", "^{"))): w("sin·cos·tan·log 앞 계수 뒤 백틱"); break
    if re.search(r"[0-9)}](?:sin|cos|tan|log|ln)\b", eq): w("sin·cos·tan·log 앞 계수 뒤 백틱")
    for m in re.finditer(r"log\s*_\s*\{([^}]*)\}", eq):
        b = m.group(1).strip()
        if not (b.startswith("`") and b.endswith("`")): w("로그의 밑 양쪽 백틱")
    for m in re.finditer(r"->", eq):
        if not eq[:m.start()].rstrip().endswith("`") or not eq[m.end():].lstrip().startswith("`"): w("극한 화살표 양쪽 백틱"); break
    if re.search(r"(therefore|because)(?!\s*``)", eq) and body not in ("therefore", "because"): w("therefore·because 뒤 백틱 둘")
    if "cases" in eq and not re.search(r"#\s*&\s*#", eq): w("cases 케이스 사이 빈 줄(# & #)")
    if len(re.findall(r"(?i)\bleft\b", eq)) != len(re.findall(r"(?i)\bright\b", eq)): w("LEFT·RIGHT 짝")
    for m in re.finditer(r"[()\[\]]", eq):
        need = "left" if m.group() in "([" else "right"
        if not re.search(r"(?i)\b" + need + r"\s*$", eq[:m.start()]): w("괄호는 전부 LEFT( RIGHT)·LEFT[ RIGHT]"); break
    if re.search(r"\b(?:RARROW|LARROW|LRARROW)\b", eq) and body not in ("RARROW", "LARROW", "LRARROW") and "eqalign" not in eq: w("화살표는 식을 나누어 $A$   $RARROW$   $B$ 꼴로")
    if re.search(r"\brm\s+[A-Za-z]+\s*\}?[\s`]*(?:LEFT\b|_\s*\{(?!\s*it\b))", eq): w("rm 뒤에 이탤릭이 오면 it으로 되돌린다(rm P it …)")
for i, line in enumerate(open(sys.argv[1], encoding="utf-8"), 1):
    s = line.rstrip("\n")
    if re.match(r"\[그림( \d+)?:", s): continue
    if "\t" in s: print(i, "탭 문자 대신 공백 4개")
    if re.search(r"([①-⑳㉠-㉻]|\((?:가|나|다|라|마|바|사)\))(?!\[반띄쓰\])(?=[^\s,.)\]])", s): print(i, "원문자·(가) 뒤에 글자가 붙으면 [반띄쓰]:", s.strip())
    if re.match(r"(코드|정답)\s*:", s): print(i, "코드·정답 머리 줄은 쓰지 않는다")
    s = re.sub(r"\[그림 \d+\]|<<일러|\d+번", "", s)
    if s.count("$") % 2: print(i, "$ 짝이 안 맞음"); continue
    if re.search(r"\$(?: {0,2}| {4,})\$(?:RARROW|LARROW|LRARROW)\$|\$(?:RARROW|LARROW|LRARROW)\$(?: {0,2}| {4,})\$", s): print(i, "화살표 수식 양옆은 공백 세 칸")
    parts = s.split("$")
    for k in range(1, len(parts), 2):
        check_eq(i, parts[k], parts[k + 1][:1], parts[k - 1])
        if re.search(r"[가-힣]", parts[k]) and "<<일러" not in line: print(i, "수식 안 한글에는 <<일러 표시:", parts[k])
    for txt in parts[0::2]:
        if re.search(r"[A-Za-z0-9=<>+]", txt): print(i, "수식 밖 영문·숫자:", txt.strip())
```

스크립트가 못 잡는 것은 눈으로 본다: 별행 수식 앞뒤 빈 줄과 들여쓰기(공백 4개), 화면에 보여야 하는 중괄호(수열·집합)를 `LEFT{ RIGHT}`로 썼는지(맨 `{ }`는 문법용이라 스크립트가 구분하지 못한다), 함수 이름과 키 큰 괄호 사이 백틱, 식 뒤 조사의 받침, 한 줄 길이, 합답형 틀, 선분의 길이·각과 등호 사이 띄어쓰기, 명령어와 철자가 겹치는 점 이름, 로만체 뒤에 이탤릭이 이어지는 곳의 `it`(스크립트는 `rm …` 바로 뒤가 괄호나 첨자인 경우만 잡는다), 마지막 `therefore` 줄, 파일 맨 위에 코드·정답 줄이 없는지.
